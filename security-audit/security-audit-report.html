1. Sumário Executivo

A auditoria defensiva de código e arquitetura identificou um conjunto de pontos fortes relevantes na aplicação (como a proteção contra injeções SQL e a restrição de escrita direta nas tabelas da fila). Contudo, foram confirmadas 3 vulnerabilidades de severidade ALTA relacionadas a políticas de banco de dados, autenticação de funções e disparo de notificações.

2. Detalhamento Didático e Técnico dos Achados

AUD-001 — Vazamento e Manipulação da Base de Assinantes Web Push

ALTA
Entenda a brecha:

A tabela de notificações de celular dos clientes foi deixada aberta para leitura e exclusão pública. Qualquer visitante do site pode extrair a lista de todos os celulares cadastrados ou apagar as inscrições de todo mundo com uma única linha de código no navegador.

Arquivo: supabase/migrations/20260208033525_f48525e5-2c6b-4bb2-a47a-4e6e489d9ebc.sql:10-21

Causa Raiz: As políticas de Row-Level Security criadas com FOR SELECT TO anon USING (true) e FOR DELETE TO anon USING (true).

Correção Imediata:

DROP POLICY IF EXISTS "Allow anonymous select" ON public.push_subscriptions;
DROP POLICY IF EXISTS "Allow anonymous delete" ON public.push_subscriptions;
DROP POLICY IF EXISTS "Allow anonymous update" ON public.push_subscriptions;

AUD-002 — Bypass de Autenticação do Barbeiro via Função _verify_pin

ALTA
Entenda a brecha:

Foi criada uma função auxiliar interna no banco de dados para checar se o PIN está certo. Como ela não tem trava de tentativas erradas e pode ser chamada livremente pela internet, um robô consegue testar todos os 10.000 números possíveis em menos de 1 minuto e descobrir a senha do barbeiro.

Arquivo: supabase/migrations/20260207112405_b5e72a0b-d1e5-411a-91fd-8216587f29f5.sql:3-11

Causa Raiz: Falta de revogação de permissão pública para a função _verify_pin.

Correção Imediata:

REVOKE EXECUTE ON FUNCTION public._verify_pin(text) FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public._verify_pin(text) TO postgres, service_role;

AUD-003 — Invocação Não Autenticada de Push (Spam em Massa)

ALTA
Entenda a brecha:

O serviço que envia mensagens para os telefones não confere quem está chamando. Qualquer pessoa na internet pode enviar uma mensagem técnica para esse serviço e fazer os celulares dos clientes tocarem e vibrarem sem parar.

Arquivo: supabase/config.toml:3-4 e supabase/functions/send-push-notification/index.ts

Causa Raiz: Desativação de JWT na configuração sem segredo alternativo no handler Deno.

Correção Imediata: Adicionar validação de segredo de cabeçalho X-Webhook-Secret na função Edge e no trigger SQL.

3. Controles Positivos Aprovados

  • ✅ Escrita Direta Bloqueada: Nenhuma tabela de negócios aceita mutação pública direta; todas exigem RPC com validação server-side.
  • ✅ admin_credentials Isolada: Políticas estritas impedem qualquer leitura direta da tabela de credenciais.
  • ✅ Segurança contra SQLi: Utilização consistente de consultas parametrizadas e estruturadas em PL/pgSQL.
  • ✅ Variáveis de Ambiente: Abstração correta no frontend via import.meta.env sem exposição estática em bundles.
